# 現場管理台帳の書き出しを作り直す 設計

2026-11-11。利用者との対話（見本 `.superpowers/brainstorm/24602-1794232833/content/ledger-1.html`）で決めた内容。

## 目的（なぜ）

- いまの「現場管理台帳（原本 Excel）」は、V34 の雛形（`templates/現場管理台帳_V34_原本.xlsm`）に Python（openpyxl。Vercel の Python 関数 `api/export/fill.py`）で日報を書き込んでいる。
  - 雛形の行数・件数（1 日の作業員 10 行、マスターの数、31 日）を超える月は出せない。
  - 労務費は雛形の式で出すので、請負の人の人工も労務費に入ったまま。外注・名前なしの作業員・手入力の車両など、アプリで後から足した決まりと数字が合わない。
  - Python 関数・秘密の値（`GN_EXPORT_SECRET`）・雛形の同梱と、動かす仕組みが重い。
- 1 日ごとの中身は日報の PDF で足りている。台帳 Excel に求めるのは「現場全体の原価」と「出面」を Excel で見て・足して・印刷できること。
- そこで、アプリが計算した数字から Excel を**いちから**作る（exceljs。工事原価集計表の Excel・予算と実績の Excel と同じやり方）。

## ゴール

1. 出力画面の「現場管理台帳」で、**.xlsx**（マクロなし）を書き出す。集計期間は工事原価集計表と同じ「工期全体」か「日報のある月」。
2. シートは 2 枚だけ：
   - **「現場原価集計」**：アプリの工事原価集計表（PDF）と**同じ中身・同じ数字**。見出し（現場名・工事名・客先名・工期・集計期間・出力日時など）と ①〜⑦（① 原価合計 ② 採算 ③ 推移 ④ 作業員別累計 ④-2 所属別 ⑤ 取引先別 ⑥ 車両・リース ⑦ 工種別出来高［外注の行を含む］）を縦に並べる。表の中身は `cost-sections.ts` の `costSections(model)` をそのまま使う。
   - **「出面一覧」**：作業員 × 日付。月ごとに 1 つの表を縦に並べる（工期が 3 か月なら 3 つ）。列は 作業員・所属・区分（自社／常用／請負）・その月の 1 日〜末日・人工計・出勤日数。日のセルは人工。名前なしの行は人数も見える（「1.0（3名）」）。下に日ごとの合計と「うち請負」。土日は色付き。
3. 見た目は今の台帳にそろえる：紺の見出し（#1F3864・白字）、水色の帯（#D9E1F2）、日本語の字体（メイリオ）、罫線、印刷の設定（「現場原価集計」は A4 横・横 1 ページ、「出面一覧」は A3 横・横 1 ページ）、見出しの固定（ウィンドウ枠の固定）。
4. 行はデータの数だけ増える（雛形の行数の上限が無いので「出せない月」は無くなる）。
5. 合計は Excel の **SUM の式**（データの範囲。途中に行を挿入しても合計に入る）で、計算済みの値も入れておく（開いてすぐ・プレビューでも数字が見える）。
6. 数字はすべてアプリの計算から（工事原価集計表と同じ `buildCostReport`）。外注は出来高に入る、請負の人工は原価に数えない（出面には残る）、手入力の車両の燃料費も入る、労務費の決まり、などが自動でそろう。
7. 出せるのは社員と管理者だけ。協力会社は今と同じく画面に出さず、API は 403。

## やらないこと

- 1 日ごとのシート（日報の PDF で見る）。
- 雛形（xlsm）への書き込み・マクロ。V34 の雛形ファイルそのものはリポジトリに残す（`templates/` は触らない）。
- 工事原価集計表の Excel（`/api/reports/cost?format=xlsx`）の変更。これまでどおり残す。
- SQL（DB は変えない）。

## 失敗になること

- 「現場原価集計」の数字が、同じ時点・同じ期間の工事原価集計表（PDF）と 1 つでも違う。
- 協力会社のアカウントで台帳を書き出せる。
- 合計の式の範囲がずれて、データの行を数え落とす・二重に数える。式の計算結果と、入れておいた値が違う。
- 名前なしの行の人工が出面から落ちる、請負の人の人工が出面から落ちる。

## 決めたこと

- **ルート**：`GET /api/export?site=<uuid>&period=all|YYYY-MM`（パスは今のまま、クエリを工事原価集計表と同じ `period` にする）。返すのは .xlsx。ファイル名は `現場名_現場管理台帳_YYYYMMDD.xlsx`（工期全体。出力日）、`現場名_現場管理台帳_YYYY年MM月.xlsx`（月）。
- **データ**：工事原価集計表と同じ読み込み（`loadCostReportInput`）と計算（`buildCostReport`）を使う。出面一覧も同じ入力（日報の労務の行の保存値・所属の写し・常用／請負・人数）から純関数で作る。新しい DB の読み取りは作らない。
- **表の描き方**：`costSections` の表（`SectionTable`）を台帳の見た目で描く関数を作る。合計の行のうち「行の値の足し算になっている列」に印（`sumColumns`）を付け、その列だけ SUM の式にする（構成比・累計原価・進捗率・平均などは値のまま）。印は `cost-sections.ts` に足し、PDF・CSV は使わない。
- **出面の行**：作業員（マスターの id、無ければ名前）× 所属 × 区分ごとに 1 行。同じ人が月の途中で常用から請負に変わったら 2 行になる（区分ごとの人工が式で出せるように）。名前なしの行は「〇〇工務店（名前なし）」の 1 行で、日のセルは人工の値に「（3名）」を表示の書式で添える（値は人工なので足し算はそのまま）。並びは 自社 → 協力会社（名前順）→ 所属なし、その中は名前順。
- **出面の合計**：人工計＝その行の日のセルの SUM、出勤日数＝その行の日のセルの COUNT、日ごとの合計＝その列の SUM、うち請負＝区分の列が「請負」の行の SUMIF。繰越初期値は日が無いので出面一覧には入れない（④ 作業員別累計には入る。シートの下に注記）。
- **今の Python の書き出しはすべて消す**（下の「消すもの」）。Storage（`gn-exports`）への xlsm の控えの保存もやめる（過去の控えはそのまま残る）。
- **取り込みとの関係**：
  - 日報の「Excel から取り込む」は 1 日分の雛形（`現場管理日報_1日追加用_雛形.xlsm` の「1回目」シート。位置は `src/lib/import/day-sheet.ts` の `DAY_LAYOUT`）を読む。台帳の書き出しとは別の仕組みなので、そのまま動く。ただしテストが Python の `layout.py` と位置を突き合わせているので、その突き合わせだけ外す（`DAY_LAYOUT` が唯一の正になる）。
  - マスターの取り込み（V33／V34 の「マスター」シートを見出しの文字で読む。`src/lib/import/parse-sheet.ts`）も、利用者が持っている台帳ファイルを読むだけなので、そのまま動く。新しい台帳（.xlsx）にはマスターのシートが無いので、新しい台帳からマスターは取り込めない（ガイドに書く）。

- `src/lib/export/fill-client.ts`・`payload.ts`・`types.ts`（`payload.ts` の `fileNameStem` は残して移す）、`src/lib/export/query.ts` の `parseExportQuery`・`overflowNotice`（`MONTH_RE`・`contentDisposition` は残す）、`src/lib/db/export.ts` の `loadExportInput`・`loadMonthReports`、`src/lib/db/summary.ts` の `labor: 'stored'`（台帳だけが使っていた）。
- `package.json` の `test:py`、`.env.example` の `GN_EXPORT_SECRET`・`GN_EXPORT_FILL_URL`、README の「Excel 出力（Vercel の Python 関数）」の章。
- テスト：`tests/export/fill-client.test.ts`・`payload.test.ts`、`tests/export/query.test.ts` の消す関数の分、`tests/import/day-sheet.test.ts` の「Python の layout.py と同じ位置」。

## 制約

- UI は日本語、375px、44px。社員・管理者だけ。
- 文字のセルは exceljs の文字の値として書く（式にならない）。式は合計の行と出面の計算の列だけ。
- コミットの末尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。push は利用者の指示で。デプロイの後、Vercel の環境変数 `GN_EXPORT_SECRET`・`GN_EXPORT_FILL_URL` は利用者が消してよい。

## 作り手に任せること

- 列幅・行の高さ・字の大きさ・罫線の細部（見本と今の台帳に寄せる）。
- 「現場原価集計」の見出しの並べ方（見本は ① と ② を横に並べているが、行が増えても崩れないよう縦に並べてよい）。
- 署名欄（作成者・確認者・承認者）を「現場原価集計」の最後に置くか（工事原価集計表の Excel と同じなら置く）。

## 利用者に確かめたいこと（作り手は既定のまま進めてよい）

- 見本の ① は「買掛費（仕入）」と「外注費」を分け、③ は列をまとめているが、ゴール 2 の「工事原価集計表と同じ」を優先して PDF と同じ表にする（既定）。分けたいなら工事原価集計表のほうも一緒に直す。
- 書き出しは工期全体と月の両方を選べるようにする（既定）。今の台帳は月ごとだった。
- Storage への控えの保存はやめる（既定）。
