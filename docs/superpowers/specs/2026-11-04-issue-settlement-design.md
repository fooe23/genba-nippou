# 追加・変更の件ごとの精算（見込み額と確定額を分ける）設計

2026-11-04。利用者（建築事業部）との対話で決めた内容。第2計画（改）の Task 9〜13（追加・変更・減の記録と精算資料）の上に足す。

## 目的（なぜ）

追加・増・変更・減の指示を受けた時点では金額はほぼ分からず、見積書を作って提出したときに確定する。常用（工数精算）の仕事もある。いまのアプリは件に「金額見込み」を 1 つ持つだけで、予測と確定を区別して残せず、精算資料の「提案額」は実績原価からの計算値しか出せない。予測（見込み）と確定（見積提出後）を別に持ち、精算資料で確定額を優先して出す。入力は二重にならないこと。

## ゴール

- 件（gn_report_issues）に「精算の方法」「確定額」「常用単価」「確定日」を持てる。見込み額は予測として残り、上書きしない。
- 現場ごとの「追加・変更の一覧」画面で、社員・管理者が件の精算の項目を入れられる（事務所の PC で、見積が出た日にまとめて入れる使い方）。
- 精算資料（PDF・Excel）が件ごとの表になり、「見込み → 確定（一式／常用 N 人工 × 単価）／未定（提案額）」と出る。精算提案額は確定している件はその額、未定の件は実績原価からの提案額で足す。
- 原価集計表の ②「追加・増・変更・減の提案額」も同じ値（精算額）になる。
- ガイドに、3 つの精算方法と入力の場所、精算資料の読み方をしっかり書く。

## やらないこと（非ゴール）

- 作業の行ごとに確定額を割り付けること（見積は件に対して一式で出るため）。
- 請求書・見積書そのものの作成、積算書との連携（第3計画）。
- 日報の入力の流れ、作業内容の区分と根拠の件、実績原価の計算、原価集計表の他の項目を変えること。
- 協力会社アカウントに精算の項目を見せる・触らせること。

## 失敗になること（アンチゴール）

- 同じ金額を 2 か所に入れないと合わない。
- 確定額を入れたら見込み額が消える。
- 常用の件で単価を変えたら他の件の単価まで変わる。
- 月指定の精算資料で、月をまたぐ件の常用計算が月の分だけになって見積と合わない。

## 決めたこと

### 精算の方法（件ごと）

- `undecided`（未定）：既定。精算額＝その件に紐づく作業の行の提案額の合計（実績原価×(1＋経費率)×(1＋利益率)、切り上げ。減は申告額）。
- `lump_sum`（一式）：確定額を 1 つ入れる。精算額＝確定額。減の件は確定額を正で入れ、精算では負に扱う。
- `daily_rate`（常用）：常用単価（客先請求、円／人工）を件に持つ。精算額＝その件に紐づく作業の行の投入人工の合計 × 常用単価（円未満切り上げ）。確定額は入れない。
- 確定日（date、任意）：見積提出日など。表示のみ。

### データ

- `gn_report_issues`：`settlement_method text not null default 'undecided' check (in ('undecided','lump_sum','daily_rate'))`、`fixed_amount numeric check (>= 0)`、`daily_rate numeric check (>= 0)`、`fixed_on date`。既存の `amount_estimate`（見込み）はそのまま。
- `gn_sites`：`default_daily_rate numeric check (>= 0)`（この現場の常用単価の既定。件の単価の初期値。空でもよい）。
- 差分 SQL `supabase/update_2026-11-05_issue_settlement.sql`（schema_genba.sql にも反映。`npm run check:sql`）。RLS・ガードは変えない（件の update は現場メンバーに許可済み。社員・管理者の制限は Server Action で行う）。

### 入力の場所

- 新しい画面 `/sites/[siteId]/changes`「追加・変更の一覧」。社員・管理者のみ（協力会社は 404）。削除済み現場は不可。完了現場は閲覧のみ（精算の項目も変えられない）。
- その現場の件を日付順に全部（対応中・完了とも）。各行：日付・種別・本文・指示者・指示方法・見込み額・精算方法（セレクト）・確定額（一式のとき）・常用単価（常用のとき。初期値は現場の既定）・確定日・紐づく作業（行数・人工合計・実績原価合計・提案額合計）・精算額（計算結果）。
- 行ごとに「保存」。Server Action `updateIssueSettlement(issueId, input)`（Zod。`{ ok } | { ok:false, error }`）。
- 入口：現場画面に「追加・変更」リンク（「出力」の隣）、出力画面の精算資料の欄にもリンク。
- 現場の既定の常用単価は現場の編集画面（SiteForm）に「常用単価の既定（円／人工）」として追加。
- 日報画面の件の欄はいまのまま（指示を受けた日に現場で登録。精算の項目はここでは出さない）。

### 精算資料（PDF・Excel）と原価集計表

- サマリー表（区分ごと）に「精算額」列を足す。精算提案額＝当初＋追加＋増＋変更−減（各区分は精算額の合計）。
- 新しい表「件ごとの精算」をサマリーの下、明細の前に置く：件（日付・種別・本文の先頭）・見込み額・精算方法・確定額または 常用 N 人工 × 単価・確定日・紐づく行数・実績原価・提案額・精算額。件に紐づかない追加等の行は最後に「件なし」の 1 行にまとめる（精算額＝行の提案額の合計）。
- 明細一覧はいまのまま（行に 件 の列がある）。
- 期間が月のとき：一覧と区分別集計はその月の行だけ、件ごとの精算と精算提案額は月末までの累計（常用の人工も月末までの累計）。第2計画（改）の裁定と同じ。
- 原価集計表 ② の行は「追加・増・変更・減の精算額（円）」に改め、値は精算資料の精算提案額の内訳（当初を除く）と同じ。

### モデル

- `ChangeLedgerModel` に `issues: ChangeIssueSettlement[]`（上の「件ごとの精算」の列）と `unlinked`（件なしの行の人工・実績原価・提案額）を足す。`summary` の各区分に `settled`（精算額）を足し、`settlement.extra/increase/change/minus/proposed` は精算額で計算する。
- 精算額の計算は `change-model.ts` の 1 関数に書き、テストで固定する（未定／一式／常用、減の符号、月末までの累計、常用の切り上げ）。
- `CostReportInput.issues`（既存）に新しい列が乗る。

### ガイド

- 新しい章 `src/content/guide/changes.md`「追加・変更の精算」：指示を受けた日にすること（件の登録・作業内容の区分と根拠の件）、見積が出たらすること（一覧画面で精算方法と確定額／単価を入れる）、3 つの精算方法の意味と計算、精算資料の読み方（見込み→確定、件なしの行、月指定の累計）、よくある迷い（追加と増の違い、常用の単価は件ごと、減の入れ方）。`src/lib/guide.ts` の章一覧に追加。
- `input.md` の「追加・増・変更・減の記録」に「金額の確定はあとで一覧画面で」の一文、`pdf.md` の精算資料の見方を新しい表に合わせて更新、`setup.md` に現場の常用単価の既定。


### 種別ごとの数え方（利用者の回答 2026-11-04）

- 件の種別が 追加指示／増／仕様変更／減 なら、その件の精算額はそれぞれ 追加／増／変更／減 に数える。
- 客先都合（手待ち・待機）と その他 は **追加** として請求に入れる。
- やり直し は自社都合なので **精算に入れない**。件ごとの表には参考として出す（精算額の欄に「（参考）」と額を出し、合計には足さない）。
- 一式・常用の件に紐づく作業の行は、区分が何であっても、その件の精算額に置き換わる（行の提案額は数えない）。未定の件は紐づく行の提案額の合計。

### 客先向け資料に実績原価を出さない（利用者の要望 2026-11-04）

- 「追加・変更工事 精算のご提案（案）」は客先に渡すので、明細一覧の「実績原価」列と、件ごとの表の実績原価は出さない。提案額（または精算額）と申告額、人工は出す。
- 実績原価は社内向けの「追加・変更の一覧」画面でだけ見せる。

### PDF のプレビュー（利用者の要望 2026-11-04）

- 原価集計表・日報・精算資料の PDF に「プレビュー」と「ダウンロード」の 2 つのボタンを置く。プレビューはブラウザの新しいタブにそのまま表示（`Content-Disposition: inline`）、ダウンロードはこれまでどおり添付（attachment）。Route は `disposition=inline` を受けたときだけ inline にする。日報画面の PDF リンクも同じ 2 つにする。

### 私の判断（設計書のレビューで出た問いへの答え）

- **月指定のとき**：一式の件は、その件を登録した日報の日付が月末以前なら数える。常用・未定の件はその件に紐づく月末までの行で計算する。区分ごとのサマリー表の「精算額」列は月末までの累計で、列名を「精算額（累計）」にし、件数・申告額・提案額（その月だけ）とは別物であることを注記に書く。あとから確定した額は、過去の月の資料を出し直したときにも反映される（資料は出力時点の内容）。
- **精算資料に載せる件**：精算方法が一式・常用の件、または期間末までに追加・増・変更・減の行が紐づいている件。未定で行の無い件は載せない。「記録はありません」は、期間に追加等の行が無く、載せる件も無いときだけ。原価集計表 ② も同じ範囲。
- **一式の件に紐づく行が無い**（見積が先に出た）：件ごとの表に行数 0 で出し、確定額をそのまま数える。
