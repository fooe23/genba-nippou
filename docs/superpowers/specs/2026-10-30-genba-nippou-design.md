# 現場日報アプリ 設計書

作成日：2026-10-30
対象組織：オオホリ建託 建築事業部
関連資料：`templates/現場管理台帳_V33_原本.xlsm`（日報雛形）、`templates/総合実行見積書_雛形_2026年版.xlsx`（積算書雛形）、`templates/現場管理日報_入力ガイド_v23.html`（既存の入力ガイド）

---

## 1. 目的と背景

現場管理者は毎日、工事現場作業日報をExcel雛形（V33「現場管理日次／月次管理台帳」）に手入力している。この雛形は1現場・1か月で1ブック、31回分の訪問シート＋マスター＋月次集計＋現場原価集計＋出面一覧という構成で、次の弱点がある。

- 作業員・日当・車両・取引先を、現場や月が変わるたびに各ブックのマスターへ入れ直す。
- 月替わりに新ブックの作成、前月繰越の手転記、マスター再設定が要る。
- 出来高（本日の作業内容）は金額・数量を手打ちで、積算書（見積内訳）との照合がない。追加・変更・増減の請求根拠が残りにくい。
- 現場での入力がスマホに向かない。

本アプリは、スマホから日報を入力し、**Excel雛形と全く同じ形のブックを出力**し、**見やすいPDF**を出し、**積算書を紐づけて出来高を内訳数量で管理**する。Excelは原本そのものを埋めて出力するため、Excelで開いた時点で月次集計・原価集計・出面一覧の数式がそのまま働く。

### 成功の基準

- 通常日の日報入力が、現場でスマホから数分で終わる（前回コピー＋時間＋出来高数量）。
- 出力したExcelを、既存のExcel運用者が見て雛形と区別できない。
- 月替わりに人手の作業がない。
- 追加・変更・増減の請求資料を、日報と積算内訳からアプリが作れる。

## 2. 利用者と権限

| 役割 | できること |
|---|---|
| 担当者（現場管理者・作業責任者） | 割り当てられた現場の日報の入力・編集・提出、積算書の添付と自社施工の選択、Excel／PDF出力、集計の閲覧 |
| 確認者・承認者 | 担当者の権限に加えて、割り当て現場の日報の確認・承認・差戻し |
| 管理者 | 全現場の閲覧・編集、現場の登録と担当者の割当、マスター管理、繰越初期値の登録、社員・権限管理 |

- 認証は既存の業務日報アプリ（Supabase Auth、メール＋パスワード）を共用する。社員マスタ `profiles` も共用する。
- 行レベルセキュリティ（RLS）：社員（`profiles.account_type = 'employee'`）は全現場の日報を閲覧・入力できる（割り当て不要）。協力会社（`'partner'`）は `site_members` に割り当てられた現場だけ。管理者（`profiles.is_admin`）は全行。承認・差戻しは、その現場で確認者・承認者に割り当てられた人（と管理者）だけ。
- 補足：社員は全現場を読めるため、各現場の繰越初期値・担当者一覧・総請負金額も全社員が閲覧できる。
- 承認済みの日報は担当者が編集できない。管理者が承認を解除すれば編集できる。

## 3. 全体構成

| 層 | 技術 | 役割 |
|---|---|---|
| フロント | Next.js（App Router）＋ React、スマホ優先UI | 入力・閲覧・管理画面 |
| 公開 | Vercel | GitHubへのpushで自動デプロイ |
| API（JS） | Next.js Route Handlers | 通常のCRUD、積算Excelの読み取り、集計 |
| API（Python） | Vercel Python Functions（openpyxl・pdfplumber） | **Excel出力（雛形xlsmの直接埋め込み）**、積算PDFの読み取り |
| PDF出力 | サーバーでHTML→PDF（Chromium）、日本語フォント（Noto Sans JP）埋め込み | 日報PDF・集計PDF・請求資料PDF |
| 認証 | Supabase Auth（既存アプリと共用） | ログイン |
| データ | Supabase PostgreSQL（既存アプリと同一プロジェクト） | 現場日報用テーブルを追加 |
| ファイル | Supabase Storage | 積算書の元ファイル、写真、出力済みExcel／PDF |
| コード管理 | GitHub | 既存アプリとは別リポジトリ |

### Excel生成方式の決定

- **採用：Python（openpyxl、`keep_vba=True`）で雛形xlsmを読み込み、入力セルに値を書いて保存する。** 数式・書式・結合・印刷設定・VBA（行追加マクロ）が原本のまま残る。
- 不採用：ExcelJSなどJS系はVBAを保持できず.xlsxになるため、「全く同じ」を満たさない。有償ライブラリは費用に見合わない。
- openpyxlの既知の制約：拡張形式のデータ検証（プルダウン）と一部の拡張書式が保存時に落ちる。対策として、出力後に失われたプルダウンを `openpyxl` のデータ検証として再設定する（天候・請負の種類・単位・作業員名・車両名・品目名）。検証用のテストで原本との差分を確認する（§14）。

## 6. 日報入力

### 6.1 画面の流れ

1. 現場と日付を選ぶ（既定は今日）。同じ日付に既に日報があればそれを開く。
2. 見出しに `2026/11/5（当月3回目・通算18回目）` を表示する。当月N回目はその月の日報を日付順に数えた番号、通算M回目は現場の初回入場から数えた番号。番号は保存済みの日報から都度計算し、保存はしない。
3. 「前回をコピー」で、直近の日報の作業員・車両・リース品の行を複写する（数量・時間は共通値に戻す）。
4. 雛形と同じ順に6つの表を縦に並べる。各表の行は「＋追加」で無制限。
5. 重要事項・連絡事項の文章と、写真の添付。
6. 下書き保存、または提出。提出すると確認者・承認者に通知（アプリ内バッジ。メール通知は第2段階）。

### 6.2 計算ルール（雛形の数式と一致させる）

| 項目 | 計算 |
|---|---|
| 共通実働時間（H） | max((終了−開始)×24 − (休憩分＋中抜分)/60, 0) |
| 作業員の実働時間 | その作業員の開始・終了が両方空なら共通実働時間。入っていれば同じ式で個別計算（休憩・中抜が空なら共通値を使う） |
| 人工 | round(実働時間 ÷ 7.5, 2) |
| 労務費 | 日当 × 人工（日当は作業員マスターの当日有効値を複写） |
| 燃料費 | 燃費が0なら0、そうでなければ 走行距離 ÷ 燃費 × 燃料単価 |
| リース費 | 数量 × リース単価 |
| 現金購入金額／買掛仕入金額 | 数量 × 単価 |
| 歩掛 | 施工数量 ÷ 投入人工（人工が空か0なら空） |
| 作業内容の合計金額 | 施工数量 × 施工単価 |
| 本日原価合計 | 労務費計＋燃料費計＋リース費計＋現金購入計＋買掛計 |
| 本日出来高 | 作業内容の合計金額の合計 |
| 進捗率 | 累計出来高 ÷ 工事総請負金額 |

### 6.3 作業内容（出来高）の入力

- 行の「内訳から選ぶ」を押すと、確認済みの最新版の積算内訳のうち**自社施工の行**だけが工種別に出る。名称・規格で検索できる。
- 選ぶと工種・施工内容（名称＋規格）・単位・施工単価（提出単価）が入り、入力は施工数量と投入人工。
- 行の下に `契約 120㎡ ／ 累計 95㎡ ／ 残 25㎡` を表示する。累計はこの日を含む全日報の同じ内訳行の施工数量合計。
- 累計が契約数量を超える入力は保存できるが、**超過**として色を変え、超過数量を表示する。
- 内訳にない作業は「追加工事」として、工種（工種マスタから選択または自由入力）・施工内容・単位・数量・単価（任意）を手入力する。種別＝追加として印を付ける。

### 6.4 入力チェック

- 日付は現場の着工予定日より前・今日より後でも入力できるが、警告を出す。
- 作業員行は作業員名が必須。燃料行は車両・走行距離・燃料単価が必須。
- 現金・買掛の数量・単価はどちらも入れるか、金額を直接入れるかを選べる（金額直接入力時は数量1・単価＝金額として保存）。
- 提出時に、作業員が0行なら確認ダイアログを出す（休工日など）。

## 8. Excel出力

### 8.1 出力単位とファイル名

- 単位は「現場×年月」で1ブック。ファイル名は雛形の運用ルールどおり `[現場名]_[YYYY年MM月].xlsm`。
- 何月分でも、いつでも出し直せる。出力したファイルはStorageにも保存し、現場詳細から再ダウンロードできる。
- その月の日報が31回を超える場合は出力を止めて警告する（雛形の上限）。

### 8.2 処理方式

1. Python関数が `templates/現場管理台帳_V33_原本.xlsm` を `openpyxl.load_workbook(keep_vba=True)` で開く。
2. 以下の対応表に従って**入力セルだけ**に値を書く。数式セル・見出し・書式には触れない。
3. 行が足りない表には行を挿入し、数式と書式を複製し、参照を書き換える（§8.4）。
4. 落ちたプルダウン（データ検証）を再設定する。
5. 保存してダウンロードさせる。

### 8.3 対応表

| 雛形の場所 | 書く値 |
|---|---|
| 現場情報マスター D4〜D12 | 現場名、客先名、工事名、工事番号、工事概要、工事総請負金額、着工予定日、竣工予定日、請負の種類 |
| マスター A3〜E32（作業員） | この現場で使う作業員：No.、作業員名、区分、当月時点の日当、備考 |
| マスター G3〜K32（取引先） | この現場で使う取引先 |
| マスター M3〜Q22（車両） | この現場で使う車両：名称、種別、燃費、備考 |
| マスター S3〜W22（リース品） | この現場で使うリース品：品目、規格、当月時点の単価、備考 |
| マスター C36〜D65（前月繰越 人工・労務費） | 作業員ごとに、出力月より前の全日報の人工・労務費合計＋繰越初期値 |
| `N回目` F2 | 日付（その月の日報を日付順に並べた N 番目） |
| `N回目` F3／F4 | 天候／作業責任者 |

| `N回目` B21〜E23, H21〜H23 | 車両行：車両名、走行距離、燃料単価、備考（燃費は数式） |
| `N回目` B27〜E32, H27〜H32 | リース行：品目名、規格、単位、数量、備考（単価は数式） |
| `N回目` B36〜F41, H36〜H41 | 現金行：品目、規格、単位、数量、購入単価、購入先 |

| `N回目` E60 | 累計原価（この日までの本日原価合計の累計、繰越は含まない。雛形の運用どおり手入力セル） |
| `N回目` H60 | 本日出来高（＝作業内容の合計。雛形では J69 とは別の手入力セルなので同じ値を書く）。隣の K60 は雛形の数式で「本日出来高÷総請負金額」を出す。アプリ内の進捗率（累計ベース）とは定義が違うが、雛形どおりに残す |

| `N回目` B80／E80／H80／K80 | 作成者名／確認者名／承認者名／承認日（承認済みの場合のみ） |

通算回目の記載位置は、見出し部に空きセルがないため連絡事項欄の1行目とした。タイトル行（A1）末尾へ付ける案に変更する場合は、この1箇所の変更で済む。

### 8.4 行が足りない日の処理

雛形の行数：作業員10、車両3、リース6、現金6、買掛6、作業内容6。これを超える日は次の手順で行を増やす。

1. 該当表の最終明細行の直下に不足分の行を挿入する。
2. 挿入行に、直上の明細行の数式（列ごとに相対参照を行番号へ置換）と書式・結合を複製する。
3. 合計行の `SUM` 範囲を挿入後の範囲に広げる。
4. 同じシート内でその表より下にあるセルを参照している数式（本日原価集計の `=I18` など、挿入で行番号がずれるもの）を、挿入行数分ずらして書き換える。
5. 他シートからこのシートを参照している数式（月次集計、集計データ、出面一覧、現場原価集計の `'N回目'!G58` など）も同じ規則でずらす。集計データの労務行は `B8〜B17` の10行固定なので、作業員が11人以上の場合は集計データにもその回目の行を追加する。
6. 書き換えの規則はアプリが雛形のレイアウト定義（表ごとの開始行・終了行・合計行・参照元）としてコードに持つ。

この処理は openpyxl の `insert_rows` が参照を更新しないことを前提に、自前で行う。実装後、挿入ありのブックをExcelで開いて月次集計の値がアプリ内集計と一致することをテストで確認する（§14）。

### 8.5 前月繰越

- マスターシートの「作業員別 当月集計」C・D列に、出力月より前の人工・労務費の合計を書く。合計は `gn_report_lines`（労務）の該当作業員分＋ `gn_carryovers` の値。
- 繰越初期値は、アプリ導入前にExcelで記録していた現場のためのもの。管理者が現場管理画面で作業員ごとに1回だけ入力する。入力欄からガイドの該当章へ飛べる。

## 9. 積算連携

### 9.1 取り込み（Excel）

- 対象：総合実行見積書 2026年版の「内訳」シート、または同じ内訳レイアウトの積算内訳書（掛率対応）。
- 読み方：行1〜4 見出し、行5〜21 中項目（工種名と工種別合計）、行24以降が19行周期の詳細ページ。各ページの小計行（first＋17）の L列に工種キー。明細行は B 左肩ラベル、C 名称、F 規格、G 単位、H 数量、I 単価、J 金額、K 備考、M 業者単価、N 掛け率、O 提出単価。
- 数式セルは計算結果が要るため、ファイルを `data_only=True` で読む（保存済みの計算値）。計算値が無い（未保存のまま作られた）場合は数量×単価で再計算し、確認画面で注記する。
- 小計・計・前項より・次項への行は行種別で区別して保存し、出来高の選択対象から外す。

### 9.2 取り込み（PDF）

- 対象：Excelから書き出した文字PDF（押印画像が載っていてもよい）。紙をスキャンしたPDF（文字が取れない）は第1段階では対象外とし、取り込み時に「文字を読み取れませんでした」と表示する。
- 読み方：pdfplumber で単語を座標付きで取り出し、見出し行（工種名称・規格・仕様・単位・数量・単価・金額・備考）の x 位置で列の境界を決める。y 位置で行をまとめる。ページ先頭の工種名行（名称列だけに値があり備考に業者名）を工種キーとする。小計・計・次項へ・前項よりを行種別として判定する。
- 読めるのは提出単価・金額まで。業者単価と掛け率は無いので空にする。

### 9.3 読み取り結果の確認画面（必須）

- Excel・PDFどちらも、保存前に必ず通す。表形式で、工種キーの割当、行種別、名称、規格、単位、数量、単価、金額を直せる。
- 検算：各工種の明細合計と小計・計の一致、全体合計と見積表紙の金額の一致を表示し、不一致は赤で示す。
- 確認を押して初めて「確認済み」になり、出来高入力で使える。

### 9.4 版管理と増減

- 同じ現場に2回目以降の取り込みをすると「変更見積（第n版）」になる。
- 前版との突き合わせ：工種キー＋名称＋規格＋単位が一致する行を対応行とし、数量・単価・金額の差を出す。対応のない行は「追加」「削除」。
- 比較結果は積算書画面で一覧でき、請求資料（§9.6）に含める。
- 既に出来高入力で参照している行が新版で削除された場合、該当日報の行は旧版の行を参照したまま残し、画面で「旧版の行」と表示する。

### 9.5 自社施工の選択と消化状況

- 工種一覧に自社施工スイッチ。切り替えると同じ工種キーの行がまとめて変わる。工種を開くと行ごとに例外調整できる。
- 工種・行ごとに、契約数量、累計施工数量、消化率、契約金額、出来高金額、超過数量、超過金額を表示する。

### 9.6 請求資料（出来高・増減一覧）

期間（開始日・終了日）を指定して、次をまとめた資料を出す。

1. 工種別・内訳行別の出来高：契約数量、期間内施工数量、累計施工数量、消化率、施工単価、出来高金額、超過数量・超過金額
2. 追加工事行（内訳に無い作業内容行）：日付、工種、施工内容、数量、単位、単価、金額
3. 変更見積の増減（最新版と当初版の差）
4. 重要事項（追加・変更・増減の指示・依頼）の一覧と状態
5. 関連写真（作業内容行・重要事項に添付されたもの）

出力はPDF（§10）と、この一覧用の簡易Excel表（雛形とは別の、ExcelJSで作る通常のxlsx）。

## 10. PDF出力

- 雛形の印刷再現ではなく、画面でも紙でも読みやすい帳票として設計する。A4縦、日本語フォント埋め込み。
- 種類：日報PDF（1日分。見出しに現場名・日付・当月N回目・通算M回目。6つの表、原価集計、出来高、重要事項、連絡事項、作成・確認・承認者。末尾に写真ページ）、月次集計PDF、現場原価集計PDF、請求資料PDF。

- サーバーでHTMLからChromiumで生成し、Storageに保存してダウンロードさせる。将来のメール送信（第2段階）にも同じPDFを使う。
- ファイル名：`日報_[現場名]_[YYYYMMDD].pdf`（既存の運用ルールどおり）。

## 11. 月をまたぐ継続と引き継ぎ

- データに月の区切りはない。翌月もそのまま同じ現場に入力を続ける。

- Excelは何月分でも後から出せ、前月繰越は自動で埋まる。

## 13. マスター管理とExcel取り込み

- 作業員・取引先・車両・リース品・単位・天候を会社共通で管理する。日当とリース単価は改定履歴を持つ。

## 14. エラー処理とテスト

### エラー処理

- 保存は行単位でなく日報単位のトランザクションで行い、途中失敗で半端な状態を残さない。
- 通信断に備え、日報入力はブラウザ内に下書きを自動保存し、復帰時に復元を提案する。
- Excel出力・PDF出力・積算取り込みは非同期ジョブとして実行し、進行状況と失敗理由を画面に出す。
- 積算取り込みの読み取り不能行は捨てず、確認画面で赤表示して人が直す。

### テスト

- 計算ルール（§6.2）の単体テスト。雛形の数式と同じ入力で同じ結果になることを、雛形に値を入れてLibreOfficeで再計算した結果と突き合わせる。
- Excel出力の検証：出力ブックを LibreOffice で再計算し、月次集計・現場原価集計・出面一覧の値がアプリ内集計と一致することを自動テストで確認する。行挿入あり（作業員12人・車両5台）のケースを含む。
- 原本との差分検証：出力ブックと原本を openpyxl で比較し、値を書いたセル以外の数式・書式・結合・印刷設定・VBAバイナリが一致することを確認する。
- 積算取り込み：`templates/総合実行見積書_雛形_2026年版.xlsx` のテスト入力済み版と、実案件の文字PDF数件で、行数・合計金額の一致を確認する。
- RLS：担当者が他現場を読めないこと、承認済み日報を担当者が更新できないことをSQLテストで確認する。

## 16. 構築手順（概要）

1. Supabase：既存プロジェクトの SQL Editor で `supabase/schema_genba.sql` を実行（`gn_` テーブル、RLS、Storageバケット `gn-estimates` `gn-photos` `gn-exports`）。
2. GitHub：新リポジトリを作成し、Next.jsアプリと Python 関数（`api/python/`）を置く。
3. Vercel：リポジトリを連携し、`NEXT_PUBLIC_SUPABASE_URL` `NEXT_PUBLIC_SUPABASE_ANON_KEY` `SUPABASE_SERVICE_ROLE_KEY`（サーバー専用）を設定。
4. 雛形ファイルはリポジトリの `templates/` に置き、Python関数が読み込む。雛形を更新する場合はファイルを差し替え、レイアウト定義（§8.4）を合わせて更新する。
5. 管理者がマスターをExcel取り込みで登録し、現場を作成して担当者を割り当てる。移行現場は繰越初期値を入れる。
