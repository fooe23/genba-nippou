# 客先に渡す資料（精算のご提案 客先用・社内確認用・お客様用日報）設計

2026-11-06。利用者との対話（モックアップで選択 A1・B1・C1）で決めた内容。「追加・変更の件ごとの精算」（2026-11-04 設計）の上に足す。

## 目的（なぜ）

追加・変更の精算で客先と打ち合わせるとき、こちらの原価（実績原価・原価からの提案額・見込み額・経費率と利益率）は見えないほうがよく、「どの日に何をやったか」の明細と指示の根拠はできるだけ見えたほうが話しやすい。いまの「追加・変更工事 精算のご提案（案）」と日報 PDF は社内の数字を含むので、客先向けと社内向けを分ける。メール送信は作らない（PDF を保存して利用者が自分で送る）。

## ゴール

- 客先用の「追加・変更工事 精算のご提案（案）」：原価・見込み額・原価からの提案額・率の式を出さず、件ごとの金額と作業の明細（根拠）を出す。
- 社内確認用の「変更増減 社内確認用」：いまの資料をそのまま残す（名前と見出しだけ変える）。
- 「現場日報（お客様用）」PDF：日報画面から出せる、金額の無い日報。本日の作業（区分つき）・人工・その日の追加変更の件・お客様確認欄。
- 出力画面と日報画面のボタン、ガイドを揃える。

## やらないこと

- メール送信。
- 一覧画面・日報の入力・精算額の計算・社内用日報 PDF・原価集計表の変更。
- 客先用 Excel の列を社内用と揃えること（客先用 Excel は客先用 PDF と同じ内容）。

## 失敗になること

- 客先用に、実績原価・見込み額・原価からの提案額・経費率/利益率・やり直しの件・件なしの内訳が 1 つでも出る。
- 客先用と社内用で、確定した件の金額が食い違う（同じ `ChangeLedgerModel` から作る。精算提案額は見積中の扱いが違うので一致しなくてよい。§6-1）。
- お客様用日報に日当・労務費・燃料/リース/購入の金額・原価集計・出来高/進捗率・連絡事項が出る。

## 決めたこと

### 1. 精算のご提案（案）客先用（PDF・Excel）

- 題名「追加・変更工事 精算のご提案（案）」、宛先「{客先名} 様 御中」、現場名・工事名・工事番号・期間、出力日。ロゴ。
- **精算のまとめ**：項目／件数／金額(円)。行：当初請負金額（未確定なら「当初見積（概算）」）、追加、増、変更、減（負）、合計行「精算提案額」。金額＝各区分の精算額（`summary[kind].settled` から、やり直しを除く）。期間が月のときは「金額（累計）」とし「件数・金額は月末までの累計」と注記。
- 注記「※ 見積中の件（N 件）は金額に含めていません。確定しだい改めてご提示します。」（N＝未定の件で紐づく行のあるもの。0 件なら出さない）。精算提案額が出せないとき（当初金額が無い）は既存の注記。
- **件ごとの内容**：件（「MM/DD-番号 種別 本文の先頭」）／ご指示（指示者／方法 指示日）／精算（「一式（見積 MM/DD）」「常用 N 人工 × ¥単価」「見積中」）／金額(円)（一式＝確定額、常用＝計算額、見積中＝「—」。減は負）／確認（客先確認あり／なし）。やり直しの件は載せない。件に紐づかない行（件なし）は、件ごとの内容には出さず、作業の明細にだけ出す（金額はまとめに含まれている）。
- **作業の明細（根拠）**：日付／区分／工種／施工内容／数量（減は負）／単位／人工／指示者／方法／件（MM/DD-番号）／確認。単価・申告額・実績原価・提案額は出さない（A1）。やり直しの件に紐づく行は出さない。
- 末尾：発行者（会社名・担当者・連絡先）とお客様確認欄（確認者・確認日・サイン）。脚注「現場日報アプリ ― 精算のご提案（案） 出力日時 ページ x / y」。
- 見積中（未定）の件の扱い：金額を出さず、精算提案額に入れない（B1）。`settlement.proposed` は社内用の値なので使わず、客先用は「当初＋確定した件の精算額（未定を除く）＋件なしの行の提案額」で計算する。
- ファイル名：`現場名_精算のご提案_YYYYMMDD.pdf|xlsx`（月は `_YYYY年MM月`）。Route：`/api/reports/changes?…&audience=client`（既定は社内用）。

### 2. 変更増減 社内確認用

- いまの「変更増減 精算資料（案）」をそのまま残し、題名を「変更増減 社内確認用」、件名行を「追加・変更の精算 社内確認」に変える。宛先「御中」は出さない。ファイル名 `現場名_変更増減_社内確認用_YYYYMMDD.…`（C1）。
- 出力画面の欄は「変更増減 精算資料」の下に「客先用（精算のご提案）」「社内確認用」の 2 組（各 PDF プレビュー／PDF ダウンロード／Excel）。

### 3. 現場日報（お客様用）PDF

- 日報画面の PDF リンクの隣に「お客様用 PDF」（プレビュー）と「お客様用 保存」。Route：`/api/reports/daily?…&format=pdf&audience=client`（date のみ。月まとめの客先用は作らない）。
- 内容：題名「現場日報（お客様用）」、現場名・日付（曜日）・天候・作業責任者・作業時間（共通時間の開始〜終了）。**本日の作業**：区分（契約内／追加／増／変更／減）・工種・施工内容・数量・単位・人工。その下に「作業員 N 名・合計 M.M 人工」。**本日の追加・変更のご連絡**：その日報に登録した件（件番号・種別・ご指示（指示者／方法）・内容本文）。無ければ「本日はありません」。**お客様確認**：記録済みなら確認者・日時・メモ、未記録なら空欄 3 つ。作成者。脚注。
- 出さないもの：作業員の氏名と時間・日当・労務費、車両・リース・現金・買掛、本日原価集計、出来高・進捗率、連絡事項、重要事項の本文（件以外）。
- 日報が無い日は「日報がありません」の 1 行（既存と同じ）。
- ファイル名 `現場名_日報（お客様用）_YYYY-MM-DD.pdf`。

### 4. モデル・共有部品

- 客先用は既存の `ChangeLedgerModel` と `DailyReportModel` から作る。客先用の表の定義は `change-sections.ts` に `client` 用の関数（`clientChangeSummary` / `clientChangeIssues` / `clientChangeDetail`）、日報は `daily-sections.ts` に `clientDailyTables`。PDF は `change-ledger.tsx` に audience 分岐（または `client-change-ledger.tsx`）、日報は `client-daily-report.tsx`。
- 客先用の精算提案額の計算は `change-model.ts` に純関数 `clientSettlement(model)` を 1 つ置き、テストで固定する（未定を除く、やり直しを除く、件なしの行は含む、減は負）。

### 5. ガイド・記録

- `changes.md` に「客先用と社内確認用の違い」「お客様用日報」の節、`excel.md`・`pdf.md` のボタンと資料の説明を更新、`approval.md` の客先確認の節に「お客様用 PDF を渡してサインをもらう」流れ。
- README の Route 一覧（`audience=client`）。記録文書。


### 6. 私の判断（設計書のレビューで出た問いへの答え）

1. **客先用と社内用の合計**：見積中の件を除くので、客先用の精算提案額は社内用の `settlement.proposed` と一致しなくてよい。失敗条件は「確定した件の金額が両資料で一致すること」に改める。社内確認用のまとめに「客先提示額（見積中を除く）」の行を 1 行足し、社内で突き合わせられるようにする。客先用の区分ごとの金額は `summary[kind].settled` を使わず、`clientSettlement(model)` が「確定した件（一式・常用）の精算額＋件なしの行の提案額」を区分ごとに計算し直す。
2. **件ごとの内容の「確認」列**：その件を登録した日報に客先確認（`client_confirmed_at`）があれば「あり」。`ChangeIssueSettlement` に `reportClientConfirmed: boolean` を足す。作業の明細の「確認」は行ごと（既存）。
3. **お客様用日報に載せる件**：やり直しは載せない。追加指示・増・仕様変更・減・客先都合・その他は載せる（重要事項の件は「施工や工事金額に影響する指示や依頼」の記録であり、客先と共有する前提）。`DailyReportModel.issues.items` に `number`・`kind`・`instructedBy`・`instructionMethod` を足す（社内用の日報 PDF には出さない）。
4. **確定額の無い一式・単価の無い常用**：客先用では「見積中」と同じ扱い（金額「—」、合計に入れない、「見積中の件（N 件）」に数える）。`clientSettlement` の規則に含めてテストで固定する。確定日が無い一式は「一式」とだけ書く。
5. **まとめの件数**：客先用では「件」＝重要事項の件。各区分の件数は、その区分の金額に数えた件の数（見積中は除く）。件なしの行は件数に入れず金額だけ入れる。月指定のときの件数も同じ規則（月末までに確定した件で、その区分に数えたもの）。
6. **ご指示の日付**：件を登録した日報の日付を使う（「施主様／口頭 11/02」）。行の指示日は作業の明細に出す。
7. **宛先の敬称**：客先名が「様」または「御中」で終わっていればそのまま、「株式会社」「有限会社」「合同会社」「（株）」「(株)」「（有）」を含めば「御中」、それ以外は「様」を付ける。客先名が無ければ「お客様 各位」。

## 制約

- 帳票の金額は保存値だけ。PDF は A4 縦、Noto Sans JP、禁則、行の途中で切れない。UI は日本語、375px、44px。協力会社は出力不可（既存の Route のゲート）。
- SQL の変更は無い。

## 作り手に任せること

- 客先用の列幅と文字の大きさ（明細は 10 列なので 1 段で収まるはず）。
- Excel の見た目（PDF と同じ内容であればよい）。
- お客様用日報の 1 ページ化（作業が多ければ 2 ページ可）。
