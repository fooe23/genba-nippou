# 作業員の所属（自社／協力会社）と常用・請負の区分 設計

2026-11-06。利用者との対話で決めた内容。

## 目的（なぜ）

協力会社の職長にも日報を入れてもらう。自社が元請・1 次のどちらでも、協力会社（2 次を含む）の作業員や、パートナーの現場にヘルプで入る自社社員が混ざる。社内では「社員か、どの協力会社か」を分けて労務管理・原価管理・追加精算に使いたいが、客先向けの資料では所属を一切見せたくない（安全書類の関係）。

## ルール（利用者と確認済み）

- **外注の作業員は買掛にしない**。人が来て働いた分は、自社・協力会社・2 次を問わず、すべて日報の作業員の行（人工 × 設定日当）で記録する。買掛は材料・物品・人の出入りを伴わない外注工事一式に限る。ガイドに明記する。
- 協力会社の作業員にも**設定日当**を持たせ、常用の日も請負の日も労務費（原価）に入れる（労務管理・原価管理・追加精算のため）。
- 「常用／請負」は**支払い・精算の区分**（原価の計算は変えない）。
- 使った作業員は削除せず無効で残す。一度も日報で使っていない作業員だけ削除できる。
- 社内用の資料・画面では所属を表示し、所属別の小計を出す。お客様用（精算のご提案・お客様用日報）には所属・会社名・社員何名などの内訳を一切出さない。

## ゴール

1. 作業員マスターに「所属」：自社、または協力会社（取引先マスターの 1 社）。2 次の場合は「上位の協力会社（1 次）」も持てる。
2. 協力会社アカウントに「所属する協力会社」（取引先マスターの 1 社）を結び付け、その職長の日報では、作業員の選択肢を自社の作業員ではなく**その会社と、その会社を上位に持つ 2 次の会社の作業員**だけにする。
3. 日報の作業員の行に「常用／請負」（所属が協力会社の作業員のときだけ表示。既定は常用）。
4. 現場ごとに協力会社別の「請負金額」を登録できる。
5. 原価集計表（社内用）に「④-2 所属別の人工・労務費」を足す：自社／協力会社（1 次ごと、内訳に 2 次）／手入力（所属なし）。協力会社は常用と請負の人工・労務費を分け、請負金額と「請負の日の人工 × 設定日当」を並べる。作業員別累計にも所属の列。
6. 社内用はすべて所属が分かるようにする（利用者の確認 2026-11-06）：変更増減 社内確認用の明細と追加・変更の一覧に、件ごとの人工の内訳「自社 M.M／協力会社名 M.M（2 次は上位会社も）」を出す。日報画面（社内）の作業員の表にも所属を小さく表示する。お客様用の資料は変更なし（所属・会社名・内訳を出さない）ことをテストで固定する。
7. 作業員マスターに「削除」（日報・繰越で一度も使っていない作業員だけ。使っている作業員にはボタンを出さず「使用中のため無効にしてください」）。

## やらないこと

- 社員のログインアカウントの作成・削除（業務日報アプリ側の機能のまま）。
- 協力会社への支払い明細書・請求書の作成。
- 原本 Excel（V34）の様式の変更（所属は載せない）。

## 決めたこと

### データ

- `gn_workers`：`affiliation text not null default 'own' check (affiliation in ('own','partner'))`、`supplier_id uuid references gn_suppliers(id)`（partner のとき必須＝アプリで検証）、`parent_supplier_id uuid references gn_suppliers(id)`（2 次のとき任意）。
- `gn_report_lines`：`labor_contract text check (labor_contract in ('jouyou','ukeoi'))`（労務の行だけ。null は常用扱い）。`gn_save_report` に列を追加。
- 協力会社アカウントの会社：新テーブル `gn_partner_accounts(user_id uuid primary key references profiles(id), supplier_id uuid not null references gn_suppliers(id))`（profiles は業務日報アプリと共有なので列を足さない）。RLS：本人と管理者が読める、管理者だけ書ける。
- 現場の請負金額：新テーブル `gn_site_partner_contracts(id, site_id, supplier_id, amount numeric >= 0, note text, unique(site_id, supplier_id))`。RLS：社員・管理者が読み書き、協力会社は不可。
- 差分 SQL 1 本（`update_2026-11-07_worker_affiliation.sql`）、schema_genba.sql にも反映。verify_rls_auto.sql に新テーブルの検査を足す。

### 画面

- マスター → 作業員：所属（自社／協力会社）、協力会社（取引先から選ぶ）、上位の協力会社（任意）。一覧に所属を表示し、所属で絞り込める。未使用の作業員に「削除」。
- 管理 → アカウント：協力会社アカウントの作成・編集で「所属する協力会社」（取引先）を選ぶ。既存の協力会社アカウントは未設定のまま動く（その場合は選択肢を絞らず、いまどおり）。
- 日報の作業員の表：所属が協力会社の作業員の行に「常用／請負」のセレクト。協力会社アカウントの選択肢の絞り込み。
- 現場の編集（管理者）に「協力会社の請負金額」の欄（協力会社を選んで金額・メモ）。

### 帳票

- 原価集計表（PDF・Excel・CSV、社内用）：④ 作業員別累計に「所属」列、新しい「④-2 所属別」表。
- 変更増減 社内確認用（PDF・Excel）と追加・変更の一覧：件ごと・件なしの人工を所属別に分けた内訳（その件に紐づく日の作業員の行から、人工の比で按分する。作業内容の行は所属を持たないため）。
- お客様用 2 種は変更なし。


### 設計レビューの問いへの答え（2026-11-06）

- **日報の共有**（利用者）：1 現場 1 日 1 枚のまま。現場ごとに自社主軸か協力会社主軸かは運用で決めるので、協力会社の職長に他社の行が見えても構わない。行ごとに隠す仕組みは作らない。
- **2 次の上位**（利用者）：協力会社は 1 次・2 次まで（3 次は扱わない）。2 次の上位の 1 次は作業員マスターに持つ。
- **その日の所属を行に記録**（私の判断）：労務の行に `affiliation`・`supplier_id`・`parent_supplier_id` を保存時にマスターから写す（既存の名前・日当の写しと同じ扱い）。帳票は行の値を使い、後から所属を変えても過去の日報は動かない。移行 SQL で既存の行を自社で埋める。
- **協力会社の職長の選択肢**（私の判断）：その会社と、その会社を上位に持つ 2 次の会社の有効な作業員すべて（現場の選択とは無関係）。手入力も使える（手入力は所属なし）。会社が未設定のアカウントはいまどおり。
- **絞り込みは画面側だけ**（私の判断）：協力会社が他社の作業員を選べないのは画面の選択肢による。DB での拒否は作らない（他社の行も見える運用のため）。
- **削除の条件**（私の判断）：日報の行（ref_id）と繰越初期値のどちらにも使われていない作業員だけ。現場の選択（gn_site_workers）は一緒に外す。
- **集計の細部**（私の判断）：繰越初期値は常用扱い。月指定の原価集計表でも請負金額は現場の総額を出す。2 次の会社に請負金額を登録したら、その 1 次の下に 2 次の行として出す。

## 制約

- 帳票の金額は保存値だけ。UI は日本語、375px、44px。協力会社は出力・一覧・精算の画面に入れない（既存）。
- 既存データ：作業員はすべて自社として移行（default 'own'）。過去の労務行は常用扱い。

## 作り手に任せること

- 所属別の表の列構成と並び。
- 請負金額の入力欄の配置。
- 作業員マスター画面の絞り込みの UI。

### 変更（利用者 2026-11-06、上の記述より優先）

- **協力会社に上下を付けない**：1 次・2 次の区別と「上位の協力会社」（`parent_supplier_id`）は作らない。所属は 自社 か 協力会社（取引先の 1 社）だけ。
- **現場ごとの協力会社**：1 つの現場に自社と複数の協力会社が入れる。現場の「協力会社」欄（新テーブル `gn_site_partners(site_id, supplier_id, amount numeric null, note, unique(site_id, supplier_id))`、`gn_site_partner_contracts` の代わり）で社員・管理者がいつでも追加・削除できる。請負金額は任意。完了現場は不可。
- **スポット**は手入力。
- **協力会社の職長の選択肢**：自社の作業員＋その現場に登録された協力会社の作業員（有効なもの）＋手入力。会社が未設定のアカウントも同じ規則。
- **集計**：協力会社は会社ごとに並べる（上下の内訳なし）。社内の表示名は 自社／取引先名／所属なし。

### 変更 2（利用者 2026-11-06、上の記述より優先）

- **作業員の選択肢（全アカウント共通）**：自社の作業員（現場の選択。未選択なら有効な自社の作業員全員）＋その現場に登録された協力会社の作業員＋この日報で使っている作業員＋手入力。協力会社の作業員は現場に登録したときだけ出る（未登録の補完なし）。協力会社アカウントの会社で選択肢は絞らない（会社の結び付けは記録用）。純関数 `workersForSiteLabor(workers, selectedWorkerIds, usedIds)`。
- **協力会社の作業員は現場に入るたびに登録**：現場の「協力会社」欄で、会社ごとに作業員を選んで登録する（`gn_site_workers` に入れる。社員・管理者。完了現場は不可）。
- **ほかの現場からコピー**：別の現場の協力会社と、その作業員の登録をまとめて写す（請負金額・メモは写さない。無効な作業員は除く。既にあるものはそのまま）。
- 協力会社を現場から外すと、その会社の作業員の登録も外れる（過去の日報は行の写しなので変わらない）。
- **無効の作業員は表示しない**（利用者 2026-11-06）：作業員マスターの一覧は既定で有効な作業員だけを出し、「無効も表示（N 名）」で切り替える。無効にした作業員は日報の選択肢・現場の登録・コピーにも出ない（その日報ですでに使っている行はそのまま表示）。削除は一度も使っていない作業員だけ（使った人は無効で残す）。

### 変更 3（利用者 2026-11-06）協力会社を取引先と分ける

- 外注の作業員は買掛にしないので、協力会社は買掛の相手先（取引先）と分けて扱う。
- データは同じ `gn_suppliers` に印を足す：`is_vendor boolean not null default true`（取引先＝買掛の相手先）、`is_partner boolean not null default false`（協力会社）。両方に印を付けてもよい（材料も納める協力会社）。どちらも外すことはできない（アプリで検証）。
- マスターに「協力会社」タブを足す（is_partner の会社）。「取引先」タブは is_vendor の会社。編集画面で 2 つの印を切り替えられる。
- 選択肢：作業員の所属の協力会社・現場の「協力会社」欄・協力会社アカウントの会社＝is_partner の会社だけ。日報の買掛と現場の取引先の選択＝is_vendor の会社だけ（その日報ですでに使っている会社は表示する）。サーバーでも検証する。
- 移行：既存の取引先はすべて is_vendor のまま。作業員・現場の協力会社・協力会社アカウントで使われている会社は is_partner にする。

### 変更 4（利用者 2026-11-06）現場から協力会社の作業員を新しく登録する

- 現場の「協力会社と作業員」画面で、その現場に入っている協力会社のカードから、新しい作業員を登録できる（社員・管理者。進行中の現場だけ。協力会社アカウントは不可）。
- 入れる項目：名前（必須）・職種・日当（必須、円）・残業単価（任意）。日当の適用開始日は、管理者の新規登録と同じ扱い（作業員マスターの規則に合わせる）。
- 登録すると、作業員マスターに協力会社（その会社）として作られ、この現場に登録された状態になる。更新者が記録される。管理者は後からマスターで日当などを直せる。
- 新しい協力会社（会社そのもの）の登録は、これまでどおり管理者だけ（マスター → 協力会社）。
- DB：社員は gn_workers・gn_worker_rates に直接書けないので、権限を確かめて 1 回で作る関数 `gn_add_site_partner_worker` を用意する（差分 SQL 1 本）。
